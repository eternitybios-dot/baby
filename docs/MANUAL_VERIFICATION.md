# 手動検証手順（実環境が必要な項目）

自動テストではカバーしきれない項目です。CI では Supabase 実環境がないため、これらのテストを「成功」扱いしていません。

## 1. RLS: 他家族データへアクセスできないこと

1. 家族 A・家族 B を別々に作成（別のブラウザプロファイル推奨）
2. 家族 A で授乳記録を追加
3. 家族 B の端末で同じ記録が見えないことを確認
4. ブラウザの開発者ツール等で、別 `family_id` を指定した REST リクエストが RLS で弾かれることを確認（anon key + 自分の JWT）

## 2. Push 購読の本人限定 SELECT（004）

1. `004_security_hardening.sql` を実行
2. 夫婦それぞれで通知をオン
3. 片方の JWT で `push_subscriptions` を SELECT し、**自分の行だけ**見えることを確認

## 3. 表示名の Realtime 反映

1. 端末 A・B で同じ家族に参加
2. 端末 A で表示名を変更して保存
3. 端末 B を手動更新せず、タイムライン上の記録者名が変わることを確認

## 4. 記録 500 件超

1. テスト用に 500 件超の `care_records` を投入（スクリプトまたは繰り返し入力）
2. ホームの今日サマリーが破綻しないこと
3. 記録一覧で「さらに読み込む」により古い記録も見られること
4. グラフで期間内の件数が欠落しないこと

## 5. 通知の成功/失敗分離

1. Edge Function を止めた状態で記録を保存 → 記録は成功し、通知失敗のトーストが出る
2. Push 購読保存を失敗させる（SQL 003 未実行など）→ 「通知オン」にならず未完了メッセージが出る
3. 通知オン後に購読をサーバ側で消してアプリを開き直す → 自動再登録の成否が設定画面の表示に反映されること

## 6. 同時刻記録のページング

1. 同じ `recorded_at` の記録を複数作り、ホーム取得件数（120）の境界付近に置く
2. 記録一覧で「さらに読み込む」後も、同時刻の古い側が欠落しないこと
